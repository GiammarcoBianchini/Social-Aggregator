# Hub dati marketing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un raccoglitore giornaliero sul Mac di Giammarco che salva in SQLite i dati di Instagram, GA4, Search Console (poi Google Business) e gli export LinkedIn, e un server MCP locale che li espone a Claude.

**Architecture:** Un solo pacchetto Node/TypeScript con due ingressi: `collect` (lanciato da launchd ogni giorno, recupera i giorni mancanti per ogni fonte e scrive in SQLite) e `mcp` (server stdio registrato in Claude Desktop, solo lettura più un import). Le fonti sono moduli separati con la stessa interfaccia; le credenziali stanno nel Portachiavi.

**Tech Stack:** Node ≥ 20, TypeScript, `@modelcontextprotocol/sdk`, `zod`, `better-sqlite3`, `google-auth-library`, `exceljs`, `vitest`.

**Spec:** Project doc `automazioni/hub-dati-design.md` (copia in `docs/design.md`).

## Global Constraints

- Solo lettura verso tutte le piattaforme; nessun servizio esposto su internet.
- Nessun segreto nel repository: token e refresh token solo nel Portachiavi macOS, servizio `hub-dati`.
- Archivio: `~/Library/Application Support/hub-dati/hub.db` (override con env `HUB_DATI_DIR` nei test).
- Giorni calcolati nel fuso `Europe/Rome`, formato `YYYY-MM-DD`.
- Raccolta giornaliera alle 08:30 via launchd; ogni corsa recupera i giorni mancanti dall'ultima riuscita, entro la finestra massima della fonte.
- Instagram: account 17841405848018774 via Facebook Login sulla Pagina 114974825841062, token di Pagina senza scadenza.
- GA4: proprietà 516548637. Search Console: `sc-domain:giammarcobianchini.com` (verificare la forma esatta con l'elenco proprietà al primo login).
- Client OAuth Google: `~/.config/claude-mcp/client.json`, progetto `claude-mcp-512420`; scope `https://www.googleapis.com/auth/analytics.readonly`, `https://www.googleapis.com/auth/webmasters.readonly` (più `https://www.googleapis.com/auth/business.manage` quando GBP è concesso).
- Endpoint e nomi di metriche: verificarli sulla documentazione corrente, non a memoria.
- Testi verso l'utente (notifiche, output MCP) in italiano.

## Review Focus

1. Mac spento per giorni → la corsa successiva recupera tutti i giorni mancanti, e un giorno raccolto due volte non si duplica.
2. Token revocato o scaduto per una fonte → quella fonte va in errore, le altre girano, notifica macOS e stato visibile in `stato_raccolta`.
3. Dati non ancora definitivi (Search Console ha 2-3 giorni di ritardo, i post Instagram crescono per 30 giorni) → gli ultimi giorni si riscaricano a ogni corsa e sovrascrivono.
4. Export LinkedIn con intestazioni in italiano o fogli in ordine diverso → import riuscito o errore chiaro; reimportare lo stesso file non duplica.
5. Mac spento oltre la finestra di recupero di un'API → il buco è registrato, notificato e visibile in `stato_raccolta`, non nascosto.
6. Due corse contemporanee (launchd più avvio manuale) → la seconda esce subito senza toccare il database.
